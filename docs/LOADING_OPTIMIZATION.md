# 화면별 로딩 개선

이번 적용: 관리자 화면 진입 시 회사·계정·프로젝트 목록을 매번 모두 읽던 동작을 화면별 필요한 조회로 제한한다. 인증·회사 범위와 응답 저장 검증은 유지한다. 다음은 코드 구조를 기준으로 한 개선 순서이며 실서비스 응답시간 측정치는 아니다.

| 화면 | 적용 / 다음 개선 |
|---|---|
| 회원사 | 목록 조회 3회 → 회사 조회 1회 |
| 프로젝트 개설 | 목록 조회 3회 → 회사 조회 1회 |
| 계정 관리 | 목록 조회 3회 → 회사·계정 조회 2회. 대량 계정은 서버 검색·페이지 조회로 확장 |
| KMA 프로젝트 | 목록 조회 3회 → 회사·프로젝트 조회 2회. 상세 보고서는 선택 후 조회 |
| 교육담당자 프로젝트 | 배정 후보 때문에 3개 목록이 필요. 이후 프로젝트 선택 후 해당 회사 후보만 조회하는 전용 API 검토 |
| 검사 | 기존 저장 후 검증·한 번 이동 유지. DB 연결 풀을 도입할 경우 대기시간 측정 후 크기를 제한 |
| 보고서 | 참여자마다 사전·사후 응답을 읽던 추가 조회 2N회를 프로젝트별 일괄 1회로 축소. 대규모 응답에서 DB 집계와 다운로드 요청 시 파일 생성 검토. 결과 캐시는 사용자·회사·결과 버전별 분리 필요 |
| 공개 페이지·로그인 | 공개 정적 자산과 로그인 앱 분리 가능. Render 무료 서버의 유휴 후 시작 지연은 화면 코드 최적화와 별개 |

후속 측정: 화면별 첫 진입/재실행 시간, DB 왕복 횟수, 느린 쿼리를 먼저 기록한다. 계정 사용 중지·세션 취소 반영을 늦추는 인증 캐시는 적용하지 않는다. 유료 인스턴스 전환이나 새 인프라는 이번 작업에 포함하지 않는다.

대시보드는 단일 저장소 호출·트랜잭션에서 집계 SQL로 회사·계정·프로젝트별 완료수를 가져오며, 문항 응답 원문은 초기 집계에서 불러오지 않는다.
