# TAP Claude API 예산과 운영 기준 v1 (2026-11-23)

## 원칙

- 한 달 청구액은 부가세 포함 100달러 안이다. 계획상 쓸 수 있는 금액은 90달러다.
- Console 사용 한도로 막지 않는다. 앱이 호출하기 전에 스스로 계산해서 멈춘다.
- 크레딧이 떨어지거나 카드 결제가 실패하거나 키가 없어도 화면은 그대로 돈다. 그럴 때는 지금 쓰는 규칙 기반 문구를 보여 준다.

## 호출 1건의 최대 비용

입력 상한 × 입력 단가 + `max_tokens` × 출력 단가. 출력 상한에는 Claude가 내부에서 생각하는 데 쓰는 토큰도 들어간다.

| 기능 | 모델 | 입력 상한 | 출력 상한 | 1건 최대 | 월 배정 |
|---|---|---|---|---|---|
| 조직 리포트 해설 | Sonnet 5.5 | 20,000 | 4,000 | $0.080 | $40.0 (500건) |
| 과정 역량 태깅 | Sonnet 5.5 Batch | 7,000 | 4,000 | $0.027 | $3.3 |
| 문항 검수 | Sonnet 5.5 | 13,000 | 2,000 | $0.046 | $4.6 (100건) |
| 자유응답 요약 | Haiku 5.5 | 50,000 | 4,000 | $0.007 | $0 (국외 이전 결정 전 보류) |

| 구분 | 금액 |
|---|---|
| 운영 앱 전체 상한 (`MONTHLY_APP_LIMIT_USD`) | $50 |
| 개발·테스트 (운영과 다른 키) | $15 |
| 예비 | $25 |
| 사용 합계 | $90 |

한국어는 1글자를 1토큰으로 잡았다(실제보다 많게 잡은 값). 캐시 할인은 빼고 계산했다.

## 앱 안에서 지키는 방식 (`tap/ai_client.py`)

1. 같은 입력으로 만든 결과가 저장돼 있으면 그대로 쓴다. 호출하지 않는다.
2. `TAP_AI_ENABLED=1`과 API 키가 둘 다 없으면 호출하지 않는다.
3. 입력이 상한을 넘으면 호출하지 않는다.
4. 결제·키 오류로 멈춰 있는 동안(6시간)은 호출하지 않는다.
5. 장부(`tap_ai_usage`)에 최대 비용을 먼저 잡는다. 기능 배정액이나 앱 전체 상한을 넘으면 호출하지 않는다.
6. 호출 결과에 따라 장부를 정리한다.

| 결과 | 장부 | 이후 |
|---|---|---|
| 정상 | 실제 사용량으로 정산 | 결과 저장 |
| 크레딧 부족·결제 오류(402, billing) | 0원 | 6시간 정지 |
| 키 오류(401, 403) | 0원 | 6시간 정지 |
| 요청 과다(429) | 0원 | 1분 정지 |
| 서버 오류(5xx) 등 거절 | 0원 | 다음 요청부터 다시 시도 |
| 시간 초과·연결 끊김 | 최대 비용 그대로 | 청구됐을 수 있어 많게 잡음 |
| 답이 잘림·거절(max_tokens, refusal) | 실제 사용량 | 규칙 문구로 대체 |

어느 경우든 화면에는 오류가 아니라 규칙 기반 문구가 나온다. DB 장애로 장부를 못 읽어도 마찬가지다.

## 켜는 방법

1. Console에서 운영용 키를 만든다. 개발용 키는 따로 만들고 그 키에만 Console 한도 15달러를 건다.
2. 키를 Secret Manager에 넣는다. 이름은 `tap-anthropic-api-key`로 한다.
3. 처음 한 번은 직접 `bash deploy/gcp/03_deploy.sh`를 돌려 실행 계정에 열람 권한을 준다. GitHub Actions 배포는 권한을 바꾸지 않는다.
4. 저장소 변수 `GCP_DEPLOY_CONFIG`에 `TAP_AI_ENABLED=1`을 넣으면 다음 배포부터 켜진다. 빼면 꺼진다.
5. 운영 키의 Console 한도는 100달러로 걸어 둔다. 앱 상한이 50달러라서 닿을 일이 없는 마지막 안전장치다.

## 조직 리포트 해설 (2026-11-23 연결)

- 담당자·KMA 조직 리포트 맨 위 "한눈에 보는 해설". `tap/report_commentary.py`, `tap/report_commentary_ui.py`.
- 담당자가 버튼을 눌렀을 때만 만든다. 결과는 저장해 모두에게 보이고, 숫자가 바뀌면 이전 해설과 "새 숫자로 다시 만들기"를 보여 준다.
- 프로젝트당 월 10회. 보내는 것은 5명 이상 묶음의 집계와 추천 과정명뿐이다.
- 해설에 입력에 없는 숫자가 있으면 저장하지 않는다.
- 조직 리포트 PDF 2쪽에 같은 해설이 들어간다. 지금 숫자로 만든 해설이 있을 때만 넣고, PDF를 받을 때 API를 부르지 않는다.
- 실측: 입력 3,174토큰, 출력 656토큰, 1건 $0.013(상한 $0.080). 월 500건을 다 써도 실제로는 $7 안팎이다.

## 아직 붙이지 않은 것

- 문항 검수는 시안을 먼저 보고 붙인다.
- 과정 태깅은 Batch API로 따로 돌리는 스크립트가 필요하다. 실시간 호출 경로는 일부러 막아 두었다.
- 출시 전에 실제 프롬프트로 `count_tokens`를 재서 입력 상한을 확정한다.
